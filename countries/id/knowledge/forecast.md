# 印尼月切分案量、节点本金与每日在手预测

> 历史方法与当时版本。11月经营监控的生效规则见[变更日志](../decisions.md)。

适用：印尼长账月切供给预测及其策略测算。2026-10-27更新。当前主方法为“有效分案池＋已知合同到期计划＋历史存续/本金保留”，上游日节点迁移用于补充未来根节点及独立交叉核验。早期历史节点日均和整月本金倍率不覆盖已有的逐户资产证据。月份、队列、账龄范围、费率和校准窗口以当次确认及用户保存参数为准。

需要核验或解释版本变化时读[多方法核验](forecast-validation.md)；需要复现本次参数及原SQL时读[2026-10-27案例](forecast-case-20261027.md)。

## 1. 先固定四个日期和三个计数单位

- 数据基点：已完成取数的截止日；另记录快照分区、SQL执行时间与底表更新时间。
- 预测期间：目标月首日至末日。历史表现截止日、实收率参考月可以不同，不因更新供给而自动改写历史实绩。
- 理论应分日：由资产账龄推算到D31、D61、D91的日期，或月初老案承接日。
- 实际执行日：真实分案日志日期。停分、红日子、补分可能令它晚于理论日期。
- 月度分案：同月、同账龄首次有效承接的债务人计次；同一债务人跨账龄可分别计次。另报全期去重人数时单独计算。
- 每日节点流入：节点事件的去重债务人数。不能用月内首次分案替代所有上游日节点事件。
- 每日在手：当天仍在有效委案中的债务人数；同日跨资产、重复转派先按选定粒度合并。月累计分案不是每日在手。

日历日是本次负载的分母；若以后改成作业日，需要同时调整案件日数、人数和展示口径。

## 2. 确定有效分案池，资产宽表负责重建账龄

1. 分案资格由截止日有效委案记录确定。按资产取截止前最新有效分案/撤案状态，排序使用时间和稳定日志ID；多资产先核唯一债务人归属。
2. 当前用户确认：排除冻结组`M2-FRZ-REL`；`cultivate`是培训组，暂不进入正式策略供给。未知队列、已撤未再分、冻结释放等单列，不假设自动可分。
3. 账龄优先用`dwb.dwb_asset_period_info`的最早未结清逾期期次到期日推算；不直接采用用户指出不准确的历史分案逾期天数字段。`dwb_fox_asset_period_info`不可未经同窗、同键核验就互换。
4. 资产期次按资产×期次去重；使用期次还本流水重建基点余额。重建历史时只保留基点已存在的合同/期次，把基点后的已记录还本加回，核对分/元、负余额、重复流水及关联放大。
5. 区分“有资产逾期”和“具有效分案资格”。用ODS分案/撤案链与分层表做覆盖对照，差异须解释。不能因某日无分案就认定资产漏取或业务漏分。

相关源表：`dm_wd_decision.dwd_mission_log_valid_2_layer`、`fox_ods.ods_fox_mission_log`及撤案/资产归属表、`dwb.dwb_asset_period_info`、`fox_ods.ods_fox_asset_period_recovery`。表结构和维护状态由当次查询核实。

## 3. 月初老案与节点新案互斥

本次业务范围：M2 D31–60；M3 D61–90；M4–7 D91–210；M7+月初D211–999。它们是本次地图范围，不能自动扩大到D1000+。

对基点为`t0`、DPD为`d`的候选案件，先生成理论节点日，再应用历史存续：

`到节点b的日期 = t0 + (b - d)`

`预计节点案件量 = 候选案件量 × 同起始DPD组、金额档、预测间隔的数量存续率`

- 月初仍在该账龄范围、且不是当日刚到节点的案件，计月初老案。1号恰好D31/D61/D91只计一次节点新案，不同时计老案。
- 月中到D31、D61、D91时计对应账龄新案。同月可先在M2承接，再进入M3；所有账龄合计不是去重人数。
- M2/M3按下个账龄节点撤案重分。若专催继续覆盖M3/M4–7，拟定11月方案按D61/D91模拟撤案重分，即使共用`M2-SCQ`队列也保留节点分案本金；对照旧方案按各自确认的持案规则处理。
- 用户确认M4–7月中不撤案，催到月底；到D211不再新增一笔M7+分案。预计结清退出仍扣除，不能把留至月底等同100%存续。
- 仅在月初承接M7+，按本次可比范围处理，不把M4–7月中跨D211重复计入。

`月度案件量 = 月初老案 + 当月每日节点新案合计`

例：10/26为D40，11/1为D46，属于M2老案；10/26为D15，11/11到D31，属于M2新案；10/26为D45，可在11/1计M2老案、11/11计M3新案。实际量须再扣历史退出，不把理论候选数直接当预测分案数。

## 4. 节点本金：先算应到期，再扣历史还本与退出

**计划到期本金不等于所有剩余贷款本金。**它是在基点已知合同中，截至目标承接日前将到期的剩余应还本金，按基点状态计算、尚未扣未来新增还本。

对具有效分案资格的债务人，拆开保存：

`计划到期本金 = 当前有效资产逾期未还本金 + 已分资产承接前新增到期本金 + 同一债务人其他存量资产承接前新增到期本金`

`预计节点本金 = 计划到期本金 × 本金保留系数`

- 第三项用于避免只过滤`eligible_asset=1`而漏掉同一有效债务人的其他存量合同即将到期部分；它不授权把所有无分案资格债务人或其全部历史未分本金并入。
- 未分资产当前已逾期本金、承接后才到期本金、基点后未知新放款分别保留范围说明，不能无声纳入。若业务确认它们会一起分案，再新增可追溯项。
- 例：剩余本金1000万，当前逾期300万，承接前再到期100万，承接后才到期600万。本次计划本金为400万，再乘保留系数。
- 金额档按承接时计划到期本金定位，及时反映新增到期引起的升档。部分还款引起的逐户跨档若未模拟，须标为限制，不声称已精确预测金额档结构。
- 数量和本金分开算。本金保留系数已包含还本和离开原账龄路径的影响，不再乘数量存续率。
- “历史目标本金÷历史起点本金”的原始倍率可以大于1，因为含新增到期；只可作为独立估计或未来根节点的金额迁移代理。已显式加新增到期时，再乘这种增长倍率会重复放大。

## 5. 本金保留系数怎样取得

“本金扣减系数”在旧文件中实际表示保留比例：98%表示保留98%，扣减2%。展示时说明名称，避免用户把它当扣除比例或实收率。

对历史同一基点、同一组债务人、同一预测间隔h：

`k(h) = Σ目标日仍沿原账龄路径的实际未还本金 / Σ基点已知合同在目标日前的计划到期本金`

- 分母包含样本在基点已逾期本金及承接前新增到期本金，以基点剩余应还额计算，不先扣h天内实际还款。
- 分子用还款流水还原目标日余额，并限制原最早逾期期次在目标日仍未结清。原最早逾期期次已结清、DPD回落的案件被视为脱离原路径；不代表整户全部结清。此规则是本次历史代理，若业务仍会承接这些回落案件，应另建回落后路径，不能当成全部还款或永久消失。
- 按起始DPD分组×起点金额档×h校准；样本不足可扩大金额档，记录实际采用层级，不能把宽档代理标成精确同格。
- 本次采用9/1债务人ID模8抽样，原组不足30件用同DPD宽金额档；h为1、11、20、30、40天，中间天数线性插值。具体日期、抽样率、门槛、锚点均属本次参数，今后应随成熟数据重选。
- 本次对k取`MIN(1,比值)`。同时保留原始比值；若高于1，先核已知合同范围、日期、流水和关联，而非只封顶掩盖问题。不要把此封顶规则用于含到期增长的原始本金倍率。
- 同样金额档的数量存续率与本金系数可能来自不同样本规模，必须分别记录样本、分子、分母。不能用未结清案件比例替代本金系数。

## 6. 已知上游与未来D1分开

已知上游使用实际记录或已知有效资产，不用历史同节点日均覆盖。另用上游节点链交叉核验：

`目标节点新案(b,t) = 上游实际/预测新案(a,t-(b-a)) × 历史同批迁移率(a→b)`

D8→D31为23天、D15→D31为16天、D31→D61和D61→D91各30天。上游窗口必须按日期平移，并区分理论到节点日与真实执行日。

- 对基点之后尚未知的D1，才采用有依据的近期日均/星期结构等估计，并声明根节点窗口和预测占比。本次10/13–26日均对应10/27–31未来D1，进入11/26–30的D31；这不是永久日期规则。
- 若根节点输入已通过历史迁移矩阵换算为目标案件与本金，则在下游汇总中不要再次乘同一迁移率。保存“原始D1输入”与“已迁移目标值”的状态，避免既加新增到期又重复应用增长倍率。
- 节点新案包含已知上游新案及未来D1预测。“其中未来D1”是子集；月总量不能再额外加一次。

## 7. 红日子与补分

用户于2026-10-27向同事确认：10/25因印尼红日子停分。它解释该日应分未分及后续补分，不是资产自然增长，也不能仅据此判断漏数。

- 保存理论日期和执行日期两个字段；补分按同一节点身份归并，不能25日候选与26日补分各计一次。
- 实际每日分案/在手使用实际执行链。预测未得到目标月停分日历时显示理论日期，并注明可能顺延；不把10/25的确认推广成每周或整个11月的停分日历。
- 同月顺延通常不增加唯一节点案件数，但可能影响实际承接日本金、可作业天数、退出和负载。跨月顺延还会改变月度归属，不能一概说对收益和供给无影响。

## 8. 每日在手、人力与策略连接

从每批承接日开始逐日计算未退出案件：M2/M3到下一节点退出；M4–7按月末留案规则并扣预计结清。重复委案区间先合并，不能同时在两个组重复计在手。

`案件日数 = Σ每日在手案件数`

`月日均在手 = 案件日数 / 当月观察日数`

`所需人数 = 月日均在手 / 目标人均负载`

`人均分案 = 期间累计分案 / 人数`；`人均负载 = 月日均在手 / 人数`

保留用户指定人数/目标负载的覆盖关系；委外指定人数改变时负载及人均创佣反向联动。更改M3分流不应无依据改变M2人力。总人力是工作量和负载的结果，不能固定总人力后任意挤占账龄。

供给池与策略分流分离：同一11月预测细格池分别套10月/11月策略；不要用两个月不同案件池冒充策略增量。模式改变退出速度时应显式设假设，不能隐藏在供给量变化中。

## 9. 交付与复用

- 单独提供每日分案汇总：日期、账龄、月初老案、节点新案、其中未来D1、合计案件、分案本金；按账龄小计及全部合计。节点明细或每日在手表不能代替此表。
- 配套保留：有效池/上游输入、候选量及计划到期本金组成、系数样本与来源、每日预测链、每日在手、月度汇总和SQL文本。Excel以公式联动同一细格池，谨慎使用冻结窗口。
- 参数变化后的在手/人数、分案/本金及汇总都应重新计算；导出后复读关键公式与数值，避免缓存旧结果。源码核对与数仓回执分别留证，不能只看截图。
- 刷新时同步修改数据日期、样本窗和说明；发现旧文字与公式不一致，应按实际输入核实并更正说明。前次文件与本次数值有差异时做版本桥接，不能把历史案例值当永久基准。
- 本技能保存方法、证据索引与必要汇总例子，不保存客户逐户数据、会话或SSO凭据。
