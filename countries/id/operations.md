# 每日运行与异常处理

1. 确定业务日期为 Asia/Jakarta 昨日。北京时间 09:30 的海豚工作流先产出结果，10:00 的日报消费该批次。印尼项目 188950989872000，工作流 189376598430592，排程 1870。工作区根目录由接手人指定，下文路径均相对该目录。
2. 打开 `outputs/印尼长账每日监控/运行包/使用说明.txt`、上一级的 `最近运行状态.json`、当月 `monthly_targets/YYYY-MM.json`。核目标来源、版本、每组日历、币种及队列分配。缺当月配置时保留最近成功版。11 月的范围变更见[决策记录](decisions.md)。
3. 在已配置印尼查询网关并具备相应只读权限的环境，用该环境 Python 执行 `运行包/refresh.py`。常规刷新复用海豚已发布数据；尚未发布先查原任务，原定等待窗口至北京时间 10:30。查询在途按原回执恢复。观远单次查询上限为 5,000 万扫描行，卡片优先用预计算结果与业务日期分区。[观远数据集示例](sql/README.md)。
4. 核对业务日期、财务桥接、三档目标的月合计和每日目标、父子合计与节点本金。按工作日筛选看累计目标是否与卡片一致。冻结本金缺失时展示金额，常规小计可报率值。历史月份展示至月底，本月止于截止日。没有分案与回款的历史月份隐藏；有分案但零回款要保留。
5. 保存每日归档的 HTML、数据快照与数据核验。管理版命名为 `印尼长账龄监控_精简版_YYYYMMDD.html`。上传版去掉“复现与 AI 提示词”。在已经授权的看板发布流程中写到经营看板仓库，再读取线上内容核日期及摘要。知识库收录生成方法与历史核验样例。最近验证的看板入口为[管理版](https://maxyu-0302.github.io/overseas-collection-monitor/Id.html)。
6. 群文案按追踪目标、人民币，先报整体、各账龄、常规人催和落后模式，再报冻结＋Other。常规内催列达标、70%至不足100%、低于70%人数。AI按账龄，仅当 M7+ AI 原始序时率低于100%时提醒AI负责人。冻结人工单列。附[印尼观远看板](https://guanyuanbi.kuainiujinke.com/page/g4cd00439f12e43ee88fa4d0)。先给业务方确认全文与提醒对象，再按当次确认的群发送，逐群保留回执。回执状态未知先核对。
7. 换月先确认新目标、汇率、工作日、冻组上线日、月切路由、人员名单，再验证捞回标签、财务取数的月份和历史可比性。旧 SQL 中仍有显式 2026-11 汇率条件；机械替换截止日不足以完成换月。

## 接手时要取得的材料

实际刷新还需要内部运行包、获批月配置、历史缓存、数仓权限及已部署的结果表。生产模板和冻结人员快照含真实业务数据，按授权获取。可先用库内离线例子完成验算。查问题时，先定位日报取数日期，再区分海豚未发布、在线查询尚未完成、核验未通过、网页发布失败或群消息待确认。保留最后成功版本和对应真实日期。
