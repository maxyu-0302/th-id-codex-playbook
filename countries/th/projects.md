# 泰国项目地图

下表按业务问题归并多轮交付。查精确文件名请打开[来源目录](inventory.tsv)，里面保留早期项目和后续修订目录。月份表示证据或适用期，历史预测要用当时可见的信息复算。

| 项目 | 接手时先做什么 | 历史成果或入口关键词 |
|---|---|---|
| 策略地图、历史分格与评分 | 核对当月生效图、C卡、金额档、缺失和回补日期。对比同池的新老案及作业模式 | 月切策略归档、B2M2客群回溯、M2_500泰铢细分与5至9月回溯 |
| 9月增收专项及切流组合 | 用原地图做基准，依次重算AI与纯净切流、Additional扩池、大额高风险人机分配。按原路径扣成本，保留零切流基线 | M2_10月三方案FINAL、方案3_可联替代人机、四方案_人力安排 |
| B2对M2的后段影响 | 从进入B2的固定队列跟到实际跨D31，分开B2当段损益与M2增量。纳入自然进入M2的概率 | 方案4_B2切流与M2增收、B2_M2人工同客群、B2策略效果 |
| 节点预测、月切与验收 | 预测D31用D16成熟批次迁移，预测D61用D31成熟批次；月初存量按留存率推，数量与本金分别核验。月切后按队列、染色和缺失格对账 | 10月D61节点预测、11月长账节点重分测算、11月分案验收、11月分案重估 |
| M4老案与人力容量 | 比较扩池比例和大额筛选，按每日入池、撤案及结清计算在手峰值，再估所需坐席。月分案量与每日在手负载分别展示 | M4老案框选、大额分析、老案50%及人均负载、M2人员结构 |
| 人员汰换及节点重分 | 锁定节点前队列和资金，转人工、转出人工、同模式换手分开核算。历史比较做结构标准化和大单敏感性 | 月中人员汰换效果、D61_D91撤分案核验、D61D91重分效果 |
| 人工目标、序时与激励 | 核准正式源表与目标类型。基准、基准加Δ、倒推、批准值分别看，先保总量再调整内部账龄 | 目标制定与序时跟踪、M3基准复核、人工目标账龄重分、人工序时假设对比 |
| 净实收、财务成本与月报 | 对齐财务和策略范围；逐通进位算线路分钟；把新增现金、补记成本、历史重分类分别桥接。月报注明实际或全月预测 | 通讯成本溯源、净实收统一模板、净实收变化拆解、三份月报更新 |
| Additional、冻结与Other | 核查原池、释放队列、撤案空档和中转窗口，现金流水去重，维护计绩和同池的桥接表 | AdditionalGroup客群回溯、冻结盘活分案核验、冻结与Other核查 |
| AI供应商及降频 | 先复核推送与实际接受，再按C卡、金额、新老案和实际队列比较。分别看本人、紧联、计费量和回款 | AI供应商分客群、AI小额组降频测算、AI推送核验 |
| 动账、地址与随机分组 | 分开标签命中、展示、转人工与实收。核对随机数位和历史染色复用；多国项目按各国证据解释 | 动账随机分组核验、动账展示核验、动账分流样本、动账实验_观远看板SQL |
| 低触达捞回与RCS | 定义回看窗、在手日、有效接通时长及关系人范围。区分单日入组和滚动去重。800案历史试验与RCS新方案各用各的对照 | 低触达精筛、低触达800案试验、RCS测试方案 |
| 看板、日报及群报 | 当月目标和人员版本→数仓分区→生成→勾稽→发布→群回执。固定专题另设观察截止 | HTML需求复盘、长账每日监控、观远最新版搭建流程、海豚邮件试跑 |
| 数据底座与核验 | 回款重新归段先还原日初有效期次；快照检查分区时间、行数与唯一数。生产写入另走对应调度流程 | 历史逾期天数核验、历史账龄口径核查、债务人信用指标每日快照 |

### 仓内复算入口

- [D31/D61/D91历史节点量检查](sql/node-quality.sql)按日在手债务人取最大DPD，核验历史窗口的节点规模。
- [快照验收](sql/snapshot-check.sql)读取指标快照的总行数、唯一键、指标数和最新更新时间。
- [RCS入组容量](sql/rcs-pool.sql)可重现11月15至18日各账龄上限的候选量，替换日期时同步改分区、日列和滚动窗口。
- [历史D61节点预测核验](history/d61-validation.md)、[历史人工分层回溯](history/m2-validation.md)、[节点迁移留出检验](history/holdout.csv)保留原分析的日期与限制。
- [逐月策略原件与版本指纹](history/monthly-sources.md)、[11月D61/D91固定观察结果](history/node-review.txt)提供规则与结果的独立追溯入口。

[历史切流情景](history/strategy-scenarios.md)记录B2方案、Additional扩池、收益与人力假设。查评分覆盖用[D31/D61同池SQL](sql/d31-d61-score.sql)，查付款窗口用[Additional边界SQL](sql/additional-cash-boundary.sql)。两条查询采用原分析日期。
