# 从经营问题到可验证判断

| 问题 | 要拿到的输入 | 计算与输出 |
|---|---|---|
| 进度落后多少 | 批准的月目标、按日权重、计绩流水、币种 | 累计目标＝月目标×截至日权重和÷全期权重和。差额＝累计实收－累计目标。序时达成＝累计实收÷累计目标。月目标完成＝累计实收÷月目标。 |
| 分案量还是回收效率 | 同一范围的月内去重本金 P、在手实收 C、率 r=C/P | 同期现金差可精确拆为 (P本−P前)×r前＋P本×(r本−r前)。前项为规模，后项为率值。列新老案、账龄和模式，列清跨池重复本金。 |
| 汇总率为何变化 | 每期各层本金占比 w、层内率 r | 口径可加时，层贡献＝w本×r本−w前×r前。对称拆分用两期平均占比×率差、平均率×占比差。分层和汇总分母存在去重差时单列差额。 |
| 调目标能否解释差距 | 调前正式值、替代历史月份、极端大单、样本数 | 单列原结果和剔除最大单或前三单的敏感性结果。重分目标时检查各段之和，并区分月目标与序时节奏。 |
| 工具是否值得推广 | 固定客户分组、同长度窗口、回款人数、现金、通讯和人力增量成本 | 按最初分组评估人均实收和还款比例，报差额、区间和送达。净贡献估计＝人均实收差×适用人数－增量成本。 |

零分母显示为缺数。区分没有回款、没有该类客群和流水匹配失败。比率用底层金额重算，合计人数与本金在对应范围独立去重。历史分层折算须给出匹配覆盖、还款人数和大单集中度。

## 低还款率试验的检出能力

[历史计算工具](tools/rare_event_power.py)适用于两组人数相同、还款事件稀少的情景。安装 NumPy 后运行 `python common/tools/rare_event_power.py` 执行自检。`power(n,p0,p1,alpha)` 估计正向检出概率，`mde(n,p0,alpha)` 返回达到80%检出概率所需的测试组还款比例。历史实现枚举至每组240人还款，限每组至少240人且截断误差通过检查的情形。多重比较按当期方案选取显著性水平。该结果只衡量还款人数比例；实收金额另看波动和集中度。
